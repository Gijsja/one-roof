# Hallway and elevator landing presentation — 2026-10-02

Implemented with three authorized subagents covering design, runtime code and tests. The cutaway now has a continuous foreground hallway tread over existing above-ground floor slabs and an elevator landing for each car on each served floor. Door panels and amber/green header lights follow the real opening/loading/closing phases and timing exposed through immutable projections. Only the occupied landing opens. Hallway view conceals complete moving cabins and their passengers; arriving Residents return through their projected arrival/walking state. Facade visibility restores the previous cabin presentation.

## Integration and scope

`HallwayPresenter` owns the floor tread mesh; `ElevatorBankPresenter` owns one dynamic mesh for all landing recesses, door panels, headers and lights. Both meshes are reused and disposed with their presenters. A 30-floor/three-car test verifies that all 90 landings share one renderer. Floor additions, slab bounds changes, shaft width/car count changes and reset/cleanup follow the existing presentation coordinator. No new raster assets, package dependencies, scene edits, manual wiring, save contracts or authoritative simulation rules were needed. The undercity retains its existing corridor presentation.

This implements the view of existing circulation; it does not add explicit above-ground hallway construction or change routes. Boarding and exits remain controlled by the existing discrete transit simulation. Door positions update from tick projections; there is no new per-Resident Update loop. Renderer count is verified structurally, not a native frame-budget or City Status certification.
